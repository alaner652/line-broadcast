# LINE 群發小工具 — 商業計劃草案

> 狀態：v0.1 草稿（2026-09-13）。數字為估算，LINE 官方帳號價目請以 LINE 官網最新公告為準。

## 1. 問題

小型服務業（健身房、美容、補習班、保險/房仲業務）用**個人 LINE** 經營客戶，一位業務通常有 50～300 位客戶好友。臨時通知（颱風休館、課程異動、活動提醒）要一個一個傳，或用 LINE 的「轉傳」功能，但轉傳一次上限約 15 人、每批都要重新勾選，50 人要操作 4 批以上、100 人以上要花 20～30 分鐘，而且容易漏人。

## 2. 現有解法與空缺

| 解法 | 優點 | 為什麼沒解決問題 |
|---|---|---|
| 手動轉傳 | 免費 | 15 人一批、要人盯著、會漏 |
| LINE 群組 | 一次到位 | 客戶彼此看得到、業務不想把客戶放同一群 |
| **LINE 官方帳號 (OA) 群發** | 正規、合規、有分眾與統計 | 客戶要重新加 OA 好友（轉換率通常只有 3～5 成）、超過免費額度（約 200 則/月）要月費、業務個人品牌不見了 |
| 第三方「LINE 群發軟體」 | 一鍵發 | 多數是灰色地帶、來源不明、有盜帳號風險 |

**空缺**：業務想「用自己的個人帳號、對既有好友、一鍵發完、不用學新東西」。

## 3. 我們的解法

一個裝在業務公司 Windows 電腦上的工具：

- 業務維護兩個記事本檔：`recipients.txt`（客戶 LINE 名稱）、`message.txt`（要發的內容）
- 雙擊 `群發.cmd`，工具在 LINE 桌面版裡逐一搜尋 → 貼上 → 送出，每位間隔 6～12 秒模擬人手
- 每位結果寫進報告，失敗的可一鍵補發；全程有 log 可查
- 第一次用「先確認第一位」模式，人眼確認開對人才繼續

技術基礎：fork 自開源 MIT 專案 line-desktop-mcp，Windows 端用 AutoHotkey 驅動 LINE 桌面版 GUI；沒有碰 LINE 伺服器、沒有破解協定、不需要帳號密碼。

## 4. 必須正視的風險

| 風險 | 等級 | 說明與對策 |
|---|---|---|
| **違反 LINE 使用條款** | 高 | LINE 條款禁止未授權的自動化操作個人帳號，帳號可能被限制或停權。對策：低頻率、隨機間隔、單日上限（建議 ≤100 人/日）、只發客戶「預期會收到」的服務通知、不發行銷廣告；合約/使用說明白紙黑字告知客戶此風險由使用者承擔。 |
| **誤發** | 中高 | Windows 端搜尋聊天室沒有讀回驗證，名字打錯可能貼進別的聊天室。對策：`--manual-first`、dry-run 預覽、名稱與 LINE 顯示一字不差、建議先在測試帳號跑一輪。 |
| **LINE 桌面版改版** | 中 | GUI 自動化靠座標與快捷鍵，LINE 更新可能讓工具失效。對策：這是**持續維護的理由**，也是訂閱費的來源；每次 LINE 更新後 48 小時內出修補。 |
| **客戶電腦環境** | 中 | 需要 Node.js、AutoHotkey、LINE 桌面版、不能鎖螢幕。對策：`install.ps1` 一鍵裝；未來包成單一 exe。 |
| **法規（個資法）** | 低中 | 客戶名單存在業務自己電腦、不經過我們伺服器，個資責任在業務端；要在說明中講清楚。 |

結論：**這是一個「省時工具」而不是「行銷平台」**。定位錯了會踩線；定位對了是很好的敲門磚。

## 5. 定位與路線

三條路，建議 **A → C**：

**A. 內部工具（現在）**
給業務朋友用，順便驗證：實際省多少時間、LINE 有沒有跳警告、Windows 端穩定度。收費一次性 NT$3,000～8,000（安裝 + 教學 + 一個月修 bug），或免費換使用回饋與推薦。

**B. 小型付費工具（3～6 個月）**
針對同類業務（保險、房仲、健身教練、美容師）。
- 一次性授權 NT$4,800 + 維護訂閱 NT$300/月（LINE 改版修補、遠端協助）
- 或純訂閱 NT$490/月
- 通路：業務朋友介紹同事、業務社團；不做公開行銷（避免被 LINE 盯上）
- 目標：6 個月 30～50 位付費使用者 → 月收 NT$10k～25k。這是**副業規模**，不是創業規模。

**C. LINE 官方帳號導入服務（長期、合規、可放大）**
用 A/B 累積的客戶，順勢賣「幫你把客戶從個人 LINE 搬到 OA」：
- OA 開通、選單、自動回覆、分眾標籤設定：一次 NT$8,000～20,000
- 每月代操 / 內容排程：NT$3,000～10,000/月
- 把本工具改成「OA 加好友邀請助手」（用個人帳號發 OA 加入連結給既有客戶），成為合規的過渡橋樑
這條才有機會做成正常生意，且不會有一天因為 LINE 改版或封鎖整個歸零。

## 6. 成本

| 項目 | 估算 |
|---|---|
| 開發（已有 fork 基礎）：Windows 穩定化、驗證、包裝 | 40～60 小時 |
| 測試機：一台 Windows 電腦或 VM + 兩個 LINE 測試帳號 | NT$0～15,000 |
| 每月維護（跟 LINE 更新） | 4～8 小時/月 |
| 支援（安裝、教學、遠端） | 每位客戶首月 1～2 小時 |

## 7. 里程碑

| 週 | 目標 | 驗收 |
|---|---|---|
| W1 | 精簡 codebase（拿掉 macOS OCR / MCP 打包）、群發 CLI + log + 安裝腳本 | 本機 dry-run、macOS 實發 3 人成功 |
| W2 | Windows 實機測試：搜尋選人、多行訊息、中文輸入法、DPI 縮放 | 20 人測試名單全數正確送達、0 誤發 |
| W3 | 業務朋友上線用一次真實通知 | 節省時間紀錄、問題清單、LINE 是否有異常 |
| W4 | 決定走 B 還是直接鋪 C；寫使用說明 + 風險告知書 | 第一位付費或第一個 OA 導入案 |

## 8. 成功指標（W4 檢視）

- 每次群發人工操作時間：從 20～30 分鐘 → < 2 分鐘（設定檔 + 雙擊）
- 誤發率：0
- LINE 帳號警告 / 限制：0 次
- 業務願不願意介紹下一個人（最真實的 PMF 訊號）
